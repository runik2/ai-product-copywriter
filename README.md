# AI Product Copywriter

Небольшой production-minded MVP для тестового задания AI-разработчика: загружает два товара из YML-фида СОЮЗ-ПРИБОР, передаёт структурированные данные в LLM и сохраняет SEO-контент в JSON и Markdown.

## Что внутри

- YML parser без лишних зависимостей: название, тип, производитель, артикул, цена, ссылка, фото и параметры.
- OpenAI Chat Completions с JSON mode, низкой температурой и двумя повторными попытками.
- Проверка результата: SEO-заголовок до 70 символов, описание 800-1200 символов, 3-5 преимуществ и обязательные поля.
- Безопасный demo mode: проект запускается без API-ключа и создаёт пример результата; это удобно для ревью.
- Вывод: `output/products.json` и `output/products.md`.
- Node.js test runner, `.env.example`, понятный CLI и нулевая зависимость от фреймворков.

## Запуск

Нужен Node.js 20+.

```bash
cp .env.example .env
# добавьте OPENAI_API_KEY в .env для генерации через LLM
npm test
npm run lint
npm run generate
```

Без ключа используется demo mode. С ключом `OPENAI_API_KEY` вызывается OpenAI API. Ключ никогда не попадает в код или результат и должен храниться только в `.env`.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `OPENAI_API_KEY` | ключ API | пусто |
| `OPENAI_MODEL` | модель | `gpt-4o-mini` |
| `FEED_URL` | URL YML-фида | feed СОЮЗ-ПРИБОР |
| `OUTPUT_DIR` | папка результатов | `output` |

## Пример выбранных товаров

При запуске берутся первые два доступных предложения актуального фида:

1. **МК110-224.8Д.4Р [М01]**, ОВЕН, комбинированный модуль ввода/вывода дискретных сигналов.
2. **ПМ01-24.АВ**, ОВЕН, GSM-модем.

Состав товара не зашит в код: он каждый раз читается из указанного источника.

## Архитектура

`src/feed.js` отвечает за загрузку и разбор фида; `src/generator.js` — за LLM и demo mode; `src/schema.js` — за бизнес-валидацию; `src/format.js` — за Markdown; `src/cli.js` — за orchestration и файлы результата.

## Ограничения и развитие

Для production можно добавить JSON Schema/Ajv, пакетную обработку каталога, rate limit/backoff по HTTP-кодам, structured logging и CI. В рамках тестового задания текущая реализация остаётся компактной, воспроизводимой и легко расширяется.
